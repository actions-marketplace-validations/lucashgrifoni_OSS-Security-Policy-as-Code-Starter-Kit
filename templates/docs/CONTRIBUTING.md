# Contributing

Thanks for helping improve this project.

## Ground rules

- Be respectful; follow the Code of Conduct.
- Prefer small, focused pull requests.
- Do not commit secrets, tokens, or private keys.
- If your change affects security posture, call it out explicitly in the PR description.

## Development workflow

1. Fork and create a branch.
2. Run tests and linters locally.
3. Open a pull request with a clear description and risk notes if relevant.

## Security-sensitive changes

Changes to CI workflows, release automation, or dependency trust boundaries should receive additional review from maintainers.
