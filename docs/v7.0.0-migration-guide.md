# v7.0.0 migration guide

> **v7.0.0 is a single breaking change wrapped around several additive features.**
> The only break is the `reports/2.0` default flip (ADR-027). Everything else in
> v7.0.0 is additive and needs **no** migration. If you already pin
> `--report-json-contract`, or you do not parse `evaluation-report.json` at all,
> v7.0.0 is a no-op for you.

## Change summary

| ID | Change | Source ADR | Adopter impact | Migration effort |
|---|---|---|---|---|
| **B-FLIP** | `reports/2.0` becomes the **default** report contract | ADR-027 | Unpinned consumers of `evaluation-report.json` now receive `2.0` shape | Low to moderate (depends on dashboard count) |
| _additive_ | `export-policy` renders a profile to OPA/Rego or CEL | ADR-035 | New subcommand; opt-in | None |
| _additive_ | `export-evidence` SPDX / OSCAL / in-toto-bundle promoted to GA | ADR-034, ADR-036 | New `--format` values; opt-in | None |
| _additive_ | `evaluate --use-insights-evidence` (off by default) | ADR-033 | Verdicts unchanged unless you pass the flag | None |

Only **B-FLIP** requires action, and only if you parse the report JSON without
pinning a contract.

## B-FLIP — `reports/2.0` is now the default

`evaluate` (and the root-callback compatibility form) now writes `reports/2.0`
JSON when `--report-json-contract` is not specified. Previously the default was
`reports/1.0`. The full contract and the status-mapping table live in
[`reports-contract-v2.0.md`](reports-contract-v2.0.md).

**SARIF output, Markdown output, and exit-code semantics are unaffected.** The
flip only changes the shape of `evaluation-report.json`.

### Fastest safe upgrade (pin for one cycle)

If you cannot migrate dashboards before upgrading, pin the old contract and the
output shape does not change at all:

```text
oss-policy-kit evaluate --target . --profile <p> --report-json-contract 1.0
```

A deprecation warning prints on stderr; it does **not** fail the gate. `1.0`
stays selectable for one minor cycle, then deprecates with a warning, then is
removed in a later major.

### Migrating dashboards to `reports/2.0`

1. **Identify** every consumer that parses `evaluation-report.json`.
2. **Update the contract check** to accept `"contract_version": "reports/2.0"`.
3. **Re-map statuses** per the table in
   [`reports-contract-v2.0.md`](reports-contract-v2.0.md#mapping-from-reports10-to-reports20).
   Common gotchas:
   - `pass` → `PASS`, `fail` → `FAIL`.
   - `degraded` → `FAIL` with a per-control `degraded: true` flag.
   - `manual-review-required`, `skipped`, and `error` converge under `UNKNOWN`
     with distinct `reason` sub-field values.
   - `not-applicable` → `NOT_APPLICABLE`.
   - `self-attested` → `SELF_ATTESTED` (only produced under
     `--use-insights-evidence`; see ADR-033).
4. **Re-point per-control reads** from `status` (1.0) to `state` (2.0); the
   per-control id field is `id` in both.

### Convert historical reports offline

```text
$ python scripts/migrate-1.0-to-2.0.py \
    --input out/old/evaluation-report.json \
    --output out/new/evaluation-report.json
```

Use this to backfill dashboards that store captured `reports/1.0` outputs.

### Deprecation timeline for `reports/1.0`

- **v7.0.0**: `2.0` is the default; `1.0` selectable via `--report-json-contract=1.0`, deprecation warning on stderr.
- **A later v7.x minor**: `1.0` keeps working with the warning (one-cycle grace).
- **A later major**: `--report-json-contract=1.0` is removed; `0.3` / `0.2` follow their own legacy removal cycles.

## Additive features (no migration required)

- **`export-policy --format {rego,cel}`** (ADR-035): renders a profile into an
  OPA/Rego or CEL policy skeleton that gates a `reports/2.0`
  `evaluation-report.json`. Integration shim, not a reimplementation of the
  evaluators. See [`policy-export.md`](policy-export.md).
- **`export-evidence` GA formats** (ADR-034, ADR-036): `spdx` (SPDX 2.3 evidence
  projection), `oscal` (OSCAL 1.1 assessment-results), and `in-toto-bundle`
  (unsigned in-toto v1). See [`evidence-export.md`](evidence-export.md).
- **`evaluate --use-insights-evidence`** (ADR-033, default off): lets three
  disclosure controls treat a target's `SECURITY-INSIGHTS.yml` as self-attested
  evidence. Off by default, never overrides a deterministic `FAIL`. See
  [`insights-ingestion.md`](insights-ingestion.md#using-insights-as-control-evidence).

## Upgrade checklist

1. **Read this guide and ADR-027** (the flip rationale).
2. **Pin the previous version in CI** (`oss-policy-kit==6.7.0`) before starting.
3. **Decide your transition**: either pin `--report-json-contract=1.0` and upgrade
   now, or migrate dashboards to `2.0` first.
4. **Migrate dashboards** that parse `evaluation-report.json` using the mapping
   table in `reports-contract-v2.0.md`.
5. **Promote v7.0.0 to production CI** once dashboards are updated (or pinned).
6. **Plan removal of `--report-json-contract=1.0`** before the next major.
