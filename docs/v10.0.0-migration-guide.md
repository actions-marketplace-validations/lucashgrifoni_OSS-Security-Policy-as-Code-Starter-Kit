# v10.0.0 migration guide

v10.0.0 introduces the **normalized finding surface** (ADR-030: the
`correlate-findings` command, the `findings/1.0` artifact, and the opt-in
`evaluate --with-findings-summary` embed — see
[findings-correlation.md](findings-correlation.md)) and completes four announced
breaking cleanups. Everything else — the reports/2.0 contract, all 23 command
surfaces, exit codes, profiles — is unchanged.

## Breaking changes

### 1. The `cra-eu-ready-2-1` profile alias is removed (ADR-029)

The profile was renamed to `cra-eu-conformance-evidence-1` in v9.0.0 with a
deprecated alias for exactly one major. In v10.0.0 the alias resolves to a hard
error (exit 2) naming the canonical id — the same pattern as the v5.0.0 removals.

```diff
- oss-policy-kit evaluate --target . --profile cra-eu-ready-2-1
+ oss-policy-kit evaluate --target . --profile cra-eu-conformance-evidence-1
```

Also update any `oss-policy-kit.yaml` (`profile:` key), CI workflow, or script
pinning the old id. `init --profile cra-eu-ready-2-1` now fails before writing config.

### 2. Legacy report schema files no longer ship

`evaluation-report-v1/v2/v3.schema.json` are deleted from the wheel and from the
public `reports/schema/` mirror (the *contracts* they described were already removed
in v9.0.0, ADR-043). The mirror now carries the real current contracts:
`evaluation-report-2.0.schema.json` and `findings-1.0.schema.json`. If you pinned a
legacy schema file path, pin the v9.x git tags instead.

### 3. `scripts/migrate-1.0-to-2.0.py` is removed

The kit has been unable to *emit* `reports/1.0` since v9.0.0; the offline converter
completed its transition duty. If you still hold stored `1.0` reports to convert,
run the script from the `v9.0.3` tag:

```bash
git show v9.0.3:scripts/migrate-1.0-to-2.0.py > migrate-1.0-to-2.0.py
```

### 4. `export-evidence` requires reports/2.0 input

The renderers' silent `reports/1.0` fallback reads are removed, and with them a set
of silently-wrong outputs was fixed: SPDX annotations now carry the real
`state`/`message` (previously always `"unknown"`/empty against a 2.0 report), every
renderer reads `target_path` (previously `"unknown"`), and the chainloop envelope
stops reading a top-level `waivers` array that reports/2.0 never had. If you feed
`export-evidence --report` a stored pre-2.0 report, convert it first (see item 3).

## Not breaking (but new)

- `correlate-findings` (23rd command) and the `findings/1.0` artifact.
- `evaluate --with-findings-summary` — **opt-in and additive**: without the flag,
  evaluate output is byte-identical to v9.0.3 (fence-tested).
- `evaluate` never reads `.oss-policy-kit/findings.json`; the artifact is only ever
  produced/consumed by the findings surface.
